## Summary

[[Mental Models]], [[Frameworks]] and [[Workflows]] seem to be on some sort of continuum where
theory is applied to solve a certain problem which is then optimized and distilled into a set of
actions.

I thought this was somewhat important to write about so that I can notice this continuum and
gradually start applying things I learn and creating my own frameworks as well as workflows.

Important to note that although there can be a continuum from mental models to workflows, they
can exist without one another as well.

## Example
[[Code review protocols]]

I have a code review protocol that I guess you could call a workflow. I created this before
I made the connection with frameworks, mental models and workflows.

Example evolution. Completely hypothetical:  
-   Mental model phase
    -   You might have research that shows consistent code style in a software project reduces bugs.
    -   The research itself might show all the maths involved as well as the experiments/data used.
    -   Essentially, you distill out the useful part: _consistent code style reduces bugs_
-   Framework phase
    -   Next you realise that because of this theoretical benefit, its good to incorporate it into
        code reviews. So you include it as guidance for one of the things code reviewers should
        be on the look for.
-   Workflow phase
    -   Eventually, after many code reviews, you realise that you have some habits when doing
        code reviews.
    -   You initially look for syntax/spelling errors. Then move on to code style and language use.
    -   Then you might move on to maintainability, logical correctness etc.
    -   After you notice you have some order of steps you take every time, you formalise the steps
        into a workflow.
